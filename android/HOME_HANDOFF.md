# 3.2 홈 대시보드 · 프론트엔드 데모

기준: [현서 — 프론트엔드 3.2](https://app.notion.com/p/3f8e6fa19a83800190e7cfc990c57b82)
브랜치: feat/android/home-dashboard (최신 develop에서 분기, 기존 PR #3 병합 확인).

## 구현 범위

| 요구사항 | 구현 |
|---|---|
| 오늘 날짜·인사 | 기기 날짜, 프로필 닉네임 표시. 앱 복귀 및 자정 이후 날짜 갱신 |
| 습관 진행 | 완료/전체 수와 진행 막대. 기록 화면의 완료/취소를 홈에 반영 |
| 예정 또는 최근 식사 | 최근 식사 시간·종류·내용 예시 및 빈 상태 |
| 다음 복약 | 정적인 예정 시각 예시 표시. 앱에서 복약 시각을 계산하지 않음 |
| 빠른 기록 | 바텀시트에서 습관·식사·복약 화면 이동 |
| 시작 안내 | 각 카드의 데이터 없음 문구 및 명확한 이동 버튼 |
| 부분 실패 | 습관·식사·복약 각각 로딩/빈 상태/성공/오류. 해당 카드만 재시도 |

이전에 요청한 기록 화면 디테일 개선도 포함했습니다. 식사·복약의 실제 입력 화면은 각각 3.4·3.6 개발 범위이므로 이동 후 준비 중 안내가 표시됩니다.

## 화면 확인 순서

1. 데모 둘러보기 또는 회원가입 체험 완료 후 홈: 기록 없음과 시작 버튼 확인.
2. 홈 하단 데모 도구 → 예시 데이터 보기: 습관 1/3, 최근 식사, 다음 복약 예시 확인.
3. 습관 화면 → 완료/취소 → 오늘 탭: 진행률이 일치하는지 확인.
4. 데모 도구 → 식사만 오류 보기: 나머지 카드와 빠른 기록은 사용 가능해야 함.
5. 식사 카드 → 이 항목만 다시 시도: 다른 카드를 바꾸지 않고 식사 예시 복구.
6. 빠른 기록 → 식사 또는 복약: 준비 중 안내 및 뒤로 가기 확인.
7. 기록 없음 보기: 예시 상태 초기화. 데모 종료 시에도 완료 상태 초기화.

데모 모드 전환은 완료 상태를 초기화합니다. 실제 서버 요청과 저장은 없습니다. 일반 새로고침은 선택한 모드를 재실행하므로 부분 오류 모드에서는 식사 오류를 다시 재현합니다.

## 배워두면 좋은 개념

- Repository: 화면이 사용하는 데이터를 가져오는 역할. 현재는 예시 데이터를 반환합니다.
- 화면 상태: 각 카드가 로딩/빈 결과/성공/오류 중 하나를 가집니다. 오류를 다른 카드로 전파하지 않습니다.
- ViewModel: 홈과 기록 화면이 같은 완료 상태를 사용하도록 관리합니다.
- CI: GitHub에서 Android 컴파일·단위 테스트·Lint·APK 빌드를 자동 실행합니다.

## 성준에게 전달할 연동 기준

- API URL/JSON은 만들지 않았습니다. 현재 Kotlin 모델은 화면용이며 확정 서버 응답 모델이 아닙니다.
- 실제 습관 회차·완료 수, 최근 식사, 다음 복약 시각은 서버 계약에 맞춰 Repository/매퍼로 연결해야 합니다.
- 복약 시간 계산, 시간대 변환, 상태값 의미, 토큰 처리는 성준과 기존 계약을 따릅니다.
- 광고는 기존 정적 예시이며 광고 SDK·권한·추적 요청을 추가하지 않았습니다.
- 별도 디자인 합의는 필요하지 않으며, 실제 데이터 연동 시 날짜 기준·오류 응답·카드별 API 계약을 확인해야 합니다.

## CI 범위

Android CI는 android 경로 또는 Android workflow 변경에서 실행합니다. 백엔드 CI는 백엔드 코드/설정 또는 해당 workflow 변경에서 실행하며 문서만 바뀐 경우 제외합니다. 이번 PR은 백엔드 workflow 필터 자체를 조정하므로 그 변경 검증을 위한 백엔드 CI가 한 번 실행될 수 있습니다. 이후 Android 전용 변경은 Android CI 대상입니다.
