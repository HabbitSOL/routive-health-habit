# 2주차 — 의약품 검색 Mock

작업일: 2026-10-20 (Asia/Seoul)
기준: https://app.notion.com/p/3f8e6fa19a83800190e7cfc990c57b82
브랜치: feat/android/drug-search-mock

## 범위와 진행 순서
- 기존 로그인·회원가입·동의 데모를 재사용한다.
- 의약품 검색 → 검색 목록 → 상세 화면을 구현한다.
- 3.3 습관은 4주차, API·토큰·서버 저장은 마지막 연동 단계로 이관한다.
- 현재 데이터는 가상 제품이며 실제 효능·용법·복용 판단을 제공하지 않는다.

## 구현
- 홈의 의약품 사전 진입점 연결, 상세 뒤로 가기에서 검색어·목록 유지.
- 350ms 입력 대기, 검색 취소와 요청 세대 번호로 최신 결과만 반영.
- 최근 검색어 최대 5개: 삭제·전체 삭제, 메모리만 사용, 로그아웃 시 초기화.
- 검색어 공백·100자 초과 처리. 이름·업체명 Mock 검색, 3개씩 더 보기.
- 검색/상세 로딩·빈 결과·오류·재시도. 추가 목록 실패 시 기존 목록 유지.
- 상세: 제형·모양·색상·분할선·분류, 성분, 효능·사용법·주의사항·부작용·상호작용·보관법, 출처·갱신일.
- 누락된 데이터는 ‘정보 없음’. 갱신일이나 실제 의약품 정보를 임의 생성하지 않음.
- 개인 복약 등록은 준비 중 안내만 제공하고 저장·일정 생성 없음.
- 흰 바탕·민트 헤더·녹색 강조·둥근 카드와 직접 그린 장식 아이콘 적용.

## 현서 학습 포인트
- Repository: 화면이 데이터를 얻는 창구. 현재 Mock, 최종 단계에서 실제 서버로 교체.
- ViewModel: 검색어와 로딩/결과/오류 상태를 관리.
- 입력 대기(debounce): 타이핑이 잠시 멈춘 후 검색.
- 페이지네이션: 결과를 조금씩 추가로 가져오는 방식.

## 성준과 최종 연동 전에 확인
로컬 backend의 DrugSearchItem, DrugDetailResponse, PageResponse 필드명을 참고했으며 서버 DTO/URL/DB는 변경하지 않았다.
실제 연결 전 최신 계약, nullable 필드, 검색 조건(성분 포함), 오류 코드, 페이지 크기, 이미지 URL/출처/갱신 시각 형식을 재확인한다.
이번 모델은 HTTP 직렬화/공통 응답 래퍼에 아직 연결되지 않았다. 토큰, API 키, DB 정보 없음.

## 기기에서 확인할 순서 (아직 미실행)
1. Android Studio Run → 데모 둘러보기 → 홈 아래 의약품 사전 둘러보기.
2. ‘새봄’ 검색 → 세 항목 → 상세 진입 → 뒤로 → 검색어/목록 유지.
3. ‘SOL’ 검색 → 더 보기 → 여섯 항목 표시.
4. 없는 단어 검색 → 빈 결과 → 지우기 → 최근 검색어 삭제.
5. 데모 상태 체험 → 검색 오류 켬/끔 → 복구.
6. 상세 오류 체험 → 오류 켬/끔 → 복구.
7. 상세 누락 정보와 출처 확인 → 개인 복약 등록 준비 중 안내.
8. 키보드, 긴 검색어, 작은 화면, 큰 글꼴, 시스템 뒤로 가기 확인.

## 검증과 전달
빌드 결과는 개발 기록 참조. 이 작업에서 단위 테스트·기기 UI 테스트는 추가/실행하지 않았다.
신규 브랜치는 기존 홈 작업 HEAD에서 분기했으며, PR 게시 전에 최신 develop 및 기존 PR 병합 상태를 확인해야 한다.
이전 홈 카드 디자인의 미커밋 변경은 보존했다. 이번 작업을 원격 Push/PR 게시한 상태로 간주하지 않는다.
지정 Notion 개발 기록 페이지는 NOT_FOUND로 동기화 대기다.
