# 프로필 화면 구성 · 성준 전달용

## 최신 역할 합의

3.1은 **프론트엔드 데모 구현 완료 · 성준 서버 연동 대기**로 관리합니다. API·토큰·서버 연결은 성준이 추후 담당한다는 현서의 요청을 반영했습니다. 최신 UI/비밀번호 변경본의 빌드·기기 검증은 별도 남은 항목입니다. 3.2 프론트엔드 개발은 서버 연결을 기다리지 않고 진행할 수 있습니다.

사용자 합의: 프로필 화면 구성과 배치는 현서가 결정·구현한 뒤 성준에게 내용을 전달한다. 같은 UI 결정에 사전 승인을 다시 요구하지 않는다.
기준: [회원가입 프로필 동의 및 로그인 토큰 처리 기준](https://app.notion.com/p/3fae6fa19a8380629536e50ba6822d56).

## 화면 구성

1. 닉네임을 가장 먼저 표시. 필수, 양끝 공백 제거, 공백만 입력 불가, 최대 30자.
2. 생년월일·성별·키는 ‘선택 정보 입력하기’를 펼쳐 입력. 아무것도 입력하지 않아도 닉네임으로 입력 확인 가능.
3. 생년월일: YYYY-MM-DD, 실제 날짜, 미래 날짜 불가.
4. 성별: MALE/FEMALE/OTHER/UNSPECIFIED. 화면 표시는 남성/여성/기타/응답하지 않음. 미선택과 UNSPECIFIED는 구분.
5. 키: 1~300cm, 소수 둘째 자리까지. 몸무게 제외.
6. 흰색 배경, 녹색 버튼, 흰색 카드와 연회색 테두리. 키보드 영역 패딩 및 스크롤 적용.

## 현재 구현 범위

회원가입 입력 → 동의 선택 → 이메일 인증 체험 → 로그인 체험 → 프로필 설정 → 홈으로 이어지는 데모를 구현했습니다. 홈 → 내 정보에서 프로필 표시·수정이 가능합니다.
입력값은 ViewModel 메모리에서만 유지. 실제 회원 정보 저장, 인증 성공, 동의 또는 온보딩 완료로 취급하지 않음.
선택 정보를 접어도 입력은 유지되며 숨겨진 항목에 오류가 있으면 다시 펼쳐 안내.

내 정보에는 이니셜 아바타·닉네임·이메일, 선택 건강정보, 습관/식사/복약 이동, 동의 선택 내역, 계정 관련 안내, 데모 로그아웃을 배치했습니다. 미입력 정보와 실제 기록이 없는 통계를 가짜 수치로 채우지 않습니다. 알림과 계정 관리는 아직 안내 단계입니다.

## 회원가입 데모와 연동 전 확인 사항

- 서버 주소와 게시 약관 원문·버전이 준비되지 않아 사용자의 승인에 따라 데모로 구현했습니다.
- 이메일은 앞뒤 공백 제거·소문자 변환·최대 320자, 비밀번호는 특수문자를 포함한 8~16자 및 확인 일치 검사입니다. 길이는 Unicode 코드 포인트 기준이고 특수문자는 ASCII 문장부호/기호(!, @, # 등)입니다. 공백이나 이모지만으로는 특수문자 조건을 충족하지 않습니다.
- 필수 TERMS_OF_SERVICE / PRIVACY / SENSITIVE_HEALTH_DATA, 선택 MARKETING을 분리했습니다. 원문이나 버전을 임의 생성하지 않았고 실제 동의를 수집하지 않습니다.
- 가입·재발송·인증·로그인은 지연과 실패를 재현하는 로컬 동작입니다. 실제 가입/메일 발송/비밀번호 대조/토큰 발급이 없습니다. 재발송 30초는 서버 계약이 아닌 데모 UX 설정입니다.
- 비밀번호는 가입 체험 완료 및 로그인 체험 완료/흐름 종료 시 지웁니다. 프로필과 선택 동의는 메모리에서만 유지하고 데모 로그아웃 때 초기화합니다.
- 서버 연동 때 이메일 미인증 상태, 인증 후 로그인, 프로필 저장, 온보딩 완료의 성공/실패를 각 응답에 맞춰 연결해야 합니다.
- 토큰 보관 방식·회전/재시도 처리, 게시 약관 버전은 실제 연동 전에 확정해야 합니다. 프로필 UI 배치에 대한 재승인은 필요하지 않습니다.
- 이번 APK 빌드는 성공했습니다. 자동 테스트 및 이번 흐름의 기기 확인은 실행하지 않았습니다. 3.1 전체 완료 판정은 보류하고 3.2 추가 개발도 보류했습니다.

## 서버 연결 시 적용할 기존 계약

- GET /api/v1/users/me로 현재 값과 상태 조회.
- PATCH /api/v1/users/me: nickname, birthDate, sex, heightCm.
- 생략/null은 기존값 유지. 기존 선택값 삭제는 clearFields로 요청하며 동일 필드 값과 삭제를 함께 보내지 않음.
- 프로필 저장 성공 뒤 POST /api/v1/users/me/onboarding/complete 호출. 필수 동의 확인과 최초 완료 시각은 서버 기준.
- 저장 또는 완료 호출이 실패하면 성공 화면으로 이동하지 않음. 입력 보존·재시도·중복 요청 방지는 실제 연동 때 적용.
- 닉네임의 이모지 등 문자 길이 계산 방식은 서버 검증과 연동 시 일치 확인 필요. 현재 UI는 Unicode 코드 포인트 기준.

이 문서는 전달용 산출물이며 성준에게 메시지를 발송한 것은 아님. 프로필 화면 배치 권한의 합의가 토큰 저장·약관 정책 변경 권한까지 확장되는 것은 아님.


## 후속 변경 · 비밀번호 정책
현서 요청으로 회원가입 데모 비밀번호를 특수문자 필수·8~16자로 변경했습니다. 바이트 기준 UI 안내는 제거했습니다. 기존 서버의 최소 8자·최대 72바이트 정책보다 입력 범위를 좁힌 프론트엔드 규칙이며, 서버 정책 자체를 변경한 것은 아닙니다. 실제 연동 전 성준에게 동일한 길이 계산과 특수문자 집합을 전달해 서버 검증도 일치시켜야 합니다.

- 실제 연동 담당은 성준이며 3.1은 프론트엔드 데모 구현 완료 · 서버 연동 대기입니다.
