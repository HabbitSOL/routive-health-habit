# AI 건강습관 MVP 기능 범위 및 수용 기준

작성일: 2026-10-14  
문서 버전: v0.1  
개발 기간: 8주  
개발 인원: 성준, 현서  
문서 상태: 개발 착수 기준안

## 1. 문서 목적

이 문서는 8주 동안 구현할 AI 건강습관 서비스 MVP의 범위와 기능별 완료 조건을 정의한다. 개발 도중 요구사항이 계속 확대되는 것을 방지하고, 성준과 현서가 동일한 완료 기준으로 작업하기 위해 사용한다.

## 2. MVP 목표

사용자는 다음 핵심 흐름을 실제 Android 앱과 Spring Boot 서버에서 수행할 수 있어야 한다.

1. 회원가입 또는 로그인한다.
2. 습관을 만들고 오늘의 수행 상태를 기록한다.
3. 식사와 6개 영양값을 기록한다.
4. 의약품 사전에서 약을 검색하고 상세정보를 확인한다.
5. 사전의 약을 개인 복약 항목으로 등록한다.
6. 복약 일정을 설정하고 실제 복용 여부를 기록한다.
7. 식사 완료 시각을 기준으로 식후 복약 예정 시각을 확인한다.
8. 일간·주간 기본 통계를 확인한다.

## 3. 우선순위 정의

| 우선순위 | 의미 | 처리 원칙 |

## 5. 공통 수용 기준

모든 P0 기능은 다음 조건을 충족해야 완료로 인정한다.

- 실제 Android 앱, Spring Boot API와 MariaDB가 연결된다.
- 로그인한 사용자는 자신의 데이터만 조회·변경할 수 있다.
- 필수 입력 누락과 잘못된 값이 검증된다.
- 로딩·빈 결과·오류·재시도 상태가 화면에 존재한다.
- 버튼을 반복 선택해도 데이터가 중복 생성되지 않는다.
- 주요 날짜와 시간은 사용자 시간대로 표시된다.
- 실제 행동 시각과 앱 기록 시각을 구분할 수 있다.
- API 오류가 앱 종료가 아닌 안내 화면으로 처리된다.
- 비밀번호·토큰·민감 건강정보 원문이 로그에 남지 않는다.
- 기능별 정상·오류 시나리오가 테스트된다.

## 6. 기능별 수용 기준

### 6.1 회원가입·로그인

#### 포함 기능

- 이메일과 비밀번호 기반 회원가입
- 이메일 중복 검사
- 로그인·로그아웃
- 기본 프로필 입력
- 필수 약관·개인정보·건강정보 처리 동의

#### 수용 기준

- 유효한 이메일과 비밀번호로 회원가입할 수 있다.
- 이미 등록된 이메일은 중복 오류로 처리된다.
- 잘못된 비밀번호는 계정 존재 여부를 과도하게 노출하지 않고 실패 처리된다.
- 로그인 성공 후 보호된 화면으로 이동한다.
- 인증정보가 없거나 만료되면 로그인 화면으로 안내한다.
- 다른 사용자의 ID를 요청에 넣어도 데이터에 접근할 수 없다.
- 필수 동의를 하지 않으면 가입이 완료되지 않는다.

### 6.2 홈 대시보드

#### 포함 기능

- 오늘의 습관 진행 상태
- 최근 또는 오늘의 식사 요약
- 다음 복약 일정
- 빠른 기록 버튼

#### 수용 기준

- 로그인 후 오늘 날짜 기준 데이터가 표시된다.
- 데이터가 없으면 각 영역에 시작 안내가 표시된다.
- 습관·식사·복약 화면으로 이동할 수 있다.
- 일부 데이터 요청이 실패해도 앱 전체가 종료되지 않는다.
- 화면 재진입 또는 새로고침 시 최신 상태가 반영된다.

### 6.3 습관

#### 포함 기능

- 습관명·카테고리·적용 기간 입력
- 반복 요일과 하루 한 개 이상의 시간 설정
- 활성·중지 상태 관리
- 오늘의 예정 회차 조회
- 완료·미루기·건너뛰기 기록

#### 수용 기준

- 사용자가 습관과 반복 일정을 등록할 수 있다.
- 설정된 요일과 시간에 맞춰 예정 회차가 생성된다.
- 오늘의 목록에는 로그인 사용자의 유효한 회차만 표시된다.
- 완료 상태를 기록하면 해당 회차의 재알림이 중단된다.
- 미루기를 선택하면 서버가 계산한 다음 예정 시각을 표시한다.
- 건너뛰기는 완료율 계산에서 완료와 구분된다.
- 같은 회차의 완료 요청이 반복되어도 한 번만 반영된다.
- 일정 변경 이전의 수행 이력이 유지된다.

### 6.4 식사

#### 포함 기능

- 아침·점심·저녁·간식·야식 구분
- 실제 식사 시각과 앱 기록 시각 저장
- 한 끼에 여러 음식 등록
- 음식명·섭취량·단위 입력
- 탄수화물·단백질·지방·당·카페인·칼로리 입력 및 합산
- 선택적 식사 사진 1장
- 완료·건너뜀·미완료 상태

#### 수용 기준

- 사용자가 식사 유형과 실제 식사 시각을 입력할 수 있다.
- 음식별 섭취량과 6개 영양값을 입력할 수 있다.
- 식사 저장 후 서버가 계산한 총 영양값이 표시된다.
- 음식 기준정보가 변경되어도 과거 식사의 영양 스냅샷이 유지된다.
- 음수 섭취량과 음수 영양값은 저장되지 않는다.
- 사진 없이도 식사 기록을 저장할 수 있다.
- 사진 업로드 실패 시 식사 본문 저장 여부를 사용자가 확인할 수 있다.
- 일간·주간 합계가 선택한 기간에 맞게 표시된다.

### 6.5 의약품 사전

#### 포함 기능

- 약 이름·성분명·업체명 검색
- 페이지네이션
- 검색 결과 요약
- 의약품 상세정보
- 개인 복약 등록 연결

#### 표시 정보

- 약 이름
- 업체명
- 효능 또는 사용 목적 정보
- 사용법
- 주의사항
- 부작용
- 보관법
- 제형·색상·모양·분할선 등 제공 가능한 식별정보
- 데이터 출처와 갱신일

#### 수용 기준

- 약 이름의 일부로 검색할 수 있다.
- 검색어 앞뒤 공백과 일반적인 표기 차이가 정규화된다.
- 검색 중에는 로딩 상태가 표시된다.
- 결과가 없으면 별도의 안내와 재검색 수단이 제공된다.
- 검색 결과를 선택하면 상세정보가 표시된다.
- 제공되지 않은 상세 항목은 `정보 없음`으로 표시된다.
- 출처와 갱신일을 확인할 수 있다.
- 상세 화면에서 개인 복약 등록 화면으로 이동할 수 있다.
- 동일한 외부 의약품이 DB에 중복 적재되지 않는다.
- 화면에 의약품 정보가 진단·처방을 대신하지 않는다는 안내가 표시된다.

### 6.6 개인 복약

#### 포함 기능

- 처방약·일반의약품·영양제·운동 보충제 구분
- 사전 의약품 또는 직접 입력 항목 등록
- 복용 목적·시작일·종료일
- 회당 복용량과 단위
- 반복 요일과 회차별 시간
- 식전·식후·공복·시간 지정
- 복용·건너뜀·약 없음 상태
- 복용 중지·종료

#### 수용 기준

- 의약품 상세정보에서 개인 복약 항목을 만들 수 있다.
- 사전에 없는 영양제·보충제는 직접 입력할 수 있다.
- 일정과 회당 복용량을 등록할 수 있다.
- 서버가 생성한 예정 복용 회차를 날짜별로 조회할 수 있다.
- 실제 복용 시각과 앱 기록 시각을 별도로 저장한다.
- 같은 예정 회차의 복용 기록이 중복 생성되지 않는다.
- 중지된 복약 항목은 이후 신규 회차를 생성하지 않는다.
- 기존 복용 이력은 일정 변경이나 중지 후에도 유지된다.

### 6.7 알림과 재알림

#### MVP 기본 정책

- 습관·복약 예정 회차에 최초 알림을 생성한다.
- 미완료 상태일 때만 재알림을 생성한다.
- 재알림은 설정된 최대 횟수를 넘지 않는다.
- 완료·건너뛰기·중지 후에는 이후 재알림을 취소한다.
- 식후 복약은 실제 식사 완료 시각을 기준으로 계산한다.

#### 수용 기준

- 알림 작업의 예정·발송·실패 상태를 서버에서 확인할 수 있다.
- 동일 회차와 차수의 알림 작업이 중복 생성되지 않는다.
- 사용자가 완료 또는 복용을 기록하면 남은 재알림이 중단된다.
- 식사 완료 시각이 바뀌면 아직 발송되지 않은 식후 알림을 재계산한다.
- 앱 알림 권한이 없을 때 설정 안내가 표시된다.
- 발송 실패가 업무 기록의 손실로 이어지지 않는다.

기본 재알림 간격과 최대 횟수는 개발 전에 별도 정책으로 확정한다.

### 6.8 통계

#### 포함 기능

- 오늘·주간 습관 완료율
- 일간·주간 6개 영양값 합계
- 기간별 복약 이행률

#### 수용 기준

- 조회 기간과 사용자 시간대가 정확히 적용된다.
- 완료·건너뜀·미완료가 서로 구분된다.
- 분모가 0인 경우 0% 또는 데이터 없음으로 안전하게 표시된다.
- 기록 수정 후 통계에 최신 데이터가 반영된다.
- 통계 화면에서 원본 기록 화면으로 이동할 수 있다.

### 6.9 분석 이벤트

#### MVP 수집 대상

- 앱 실행과 로그인 성공·실패
- 주요 화면 조회
- 등록 시작·완료·실패
- 의약품 검색과 상세 조회
- 습관·복약 상태 변경
- 알림 발송·열람·알림에서 앱 진입
- 오류와 재시도

#### 수용 기준

- 이벤트 발생 시각과 서버 수신 시각을 구분한다.
- 로그인 전에는 익명 ID, 로그인 후에는 사용자 ID와 연결할 수 있다.
- 이벤트 중복 수신을 방지할 이벤트 ID가 존재한다.
- 분석 속성에 비밀번호, 토큰, 자유입력 건강정보 원문을 저장하지 않는다.
- 알림 ID와 행동 회차 ID를 연결하여 반응시간을 계산할 수 있다.

## 7. 비기능 수용 기준

### 보안

- 비밀번호는 검증된 단방향 해시로 저장한다.
- 인증 토큰과 비밀정보를 코드 저장소에 커밋하지 않는다.
- 사용자 소유 데이터 API는 인증과 소유권 검사를 수행한다.
- 민감정보 접근·변경 행위를 감사할 수 있다.

### 안정성

- 네트워크 지연과 일시적 오류가 앱 종료로 이어지지 않는다.
- 중복 POST 요청을 멱등성 키 또는 DB 제약으로 방지한다.
- DB Migration으로 빈 데이터베이스에서 구조를 재현할 수 있다.

### 성능 목표

- 시연 데이터 기준 일반 조회 API는 체감상 즉시 응답해야 한다.
- 의약품 검색은 페이지네이션을 적용한다.
- 이미지 원본은 DB에 저장하지 않는다.

### 사용성

- 주요 기능은 홈에서 세 번 이내의 선택으로 진입한다.
- 모든 목록 화면에 로딩·빈 결과·오류 상태가 존재한다.
- 의료정보에는 출처와 면책 안내가 표시된다.

## 8. MVP 제외 범위

다음 기능은 DB에 일부 구조가 존재하더라도 8주 MVP에서 실제 구현하지 않는다.

- 운동 상세 기록과 세트별 중량·횟수 관리
- Garmin·Samsung Health·Health Connect 실제 연동
- AI 음식 사진 자동 분석
- 음식 QR·바코드 자동 등록
- 알레르기 자동 판정과 경고
- 약물 상호작용 자동 판정
- DUR 연동 또는 의료적 복용 판단
- 처방전 OCR·QR 자동 입력
- 병원·의료기관 실제 연계
- 게임·캐릭터·랭킹·친구·그룹 챌린지
- 고급 신체측정 분석
- AI 개인화 추천과 질병 예측
- 결제·구독·제휴 보상

## 9. 전체 시연 수용 시나리오

다음 시나리오가 중단 없이 동작하면 MVP의 핵심 통합 조건을 충족한 것으로 본다.

1. 테스트 계정으로 로그인한다.
2. 매일 수행할 물 마시기 습관을 등록한다.
3. 오늘의 습관에서 완료 처리한다.
4. 점심 식사와 음식·영양값을 기록한다.
5. 의약품 사전에서 특정 약을 검색한다.
6. 약 상세정보와 출처를 확인한다.
7. 해당 약을 식후 30분 복약 항목으로 등록한다.
8. 점심 완료 시각을 기준으로 계산된 복약 예정 시각을 확인한다.
9. 예정 회차를 복용 완료로 기록한다.
10. 통계 화면에서 습관 완료율, 영양 합계와 복약 이행률을 확인한다.

## 10. 완료 정의

기능 완료는 화면만 보이거나 API만 동작하는 상태를 의미하지 않는다. 다음을 모두 만족해야 한다.

- [ ] 요구사항과 수용 기준을 충족한다.
- [ ] Android와 실제 API가 연결된다.
- [ ] MariaDB에 올바른 데이터가 저장된다.
- [ ] 권한·입력·중복 검증이 동작한다.
- [ ] 정상·빈 결과·오류 시나리오가 확인된다.
- [ ] 자동 또는 수동 테스트 결과가 남는다.
- [ ] OpenAPI 명세와 구현이 일치한다.
- [ ] Pull Request 검토가 완료된다.
- [ ] 시연 절차를 다른 사람이 재현할 수 있다.

- 최종 배포 범위: APK, 내부 테스트 또는 스토어 배포
