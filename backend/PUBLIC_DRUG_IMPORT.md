# 공공 의약품 데이터 적재·갱신

기준일: 2026-10-15. 서버 코드 구현 범위다. 실제 공공 API 인증키를 사용한 실호출·실데이터 적재는 아직 검증하지 않았다.

## 데이터 출처와 범위

- 공식 API: [식품의약품안전처 의약품개요정보(e약은요)](https://www.data.go.kr/data/15075057/openapi.do)
- 요청 주소: https://apis.data.go.kr/1471000/DrbEasyDrugInfoService/getDrbEasyDrugList
- 일반의약품 중 제공 대상 제품의 제품명·업체·효능·사용법·주의사항·상호작용·부작용·보관법·이미지·수정일을 사용한다.
- 처방약 전체, 영양제, 정량 성분, 모양·색·분할선·제형을 이 API가 모두 제공하는 것으로 간주하지 않는다.
- 이 적재기는 kind=OTC, 출처는 식품의약품안전처 e약은요로 저장한다.
- 의료 판단, 개인별 상호작용 판정 또는 DUR 검사 기능은 아니다. interactions는 출처가 제공한 일반 주의 설명이다.

## 실행 방식

기본값은 비활성이다. 일반 앱 사용자에게 적재 HTTP API를 제공하지 않는다.
운영자가 로컬/배포 환경변수를 지정한 단일 인스턴스를 시작할 때 1회 실행한다.
실행 후 서버는 계속 동작한다. 정기 스케줄이나 별도 무한 반복은 등록하지 않았다.

| 환경변수 | 기본값 | 의미 |
| --- | --- | --- |
| MFDS_IMPORT_ON_STARTUP | false | 명시적으로 true인 경우 시작 시 적재 |
| MFDS_SERVICE_KEY | 미설정 | 포털의 일반 인증키(Decoding)를 환경변수로 전달 |
| MFDS_IMPORT_START_PAGE | 1 | 시작 페이지(1부터) |
| MFDS_IMPORT_MAX_PAGES | 100 | 실행당 최대 페이지 수, 1~1000 |
| MFDS_IMPORT_PAGE_SIZE | 100 | 페이지당 요청 건수, 1~100 |

필수 준비:

1. 공공데이터포털에서 해당 API 활용신청·승인 및 인증키 발급.
2. MariaDB와 Java 21을 준비하고 DB 접속 환경변수 설정.
3. MFDS_SERVICE_KEY를 로컬 환경변수나 배포 비밀값으로 등록.
4. 처음에는 MAX_PAGES=1로 확인하고 원하는 범위로 확대.

```powershell
# 인증키는 별도 환경 설정에서 준비한다. 실제 값을 코드·문서에 적지 않는다.
$env:MFDS_IMPORT_ON_STARTUP = 'true'
$env:MFDS_IMPORT_MAX_PAGES = '1'
$env:MFDS_IMPORT_PAGE_SIZE = '100'
.\mvnw.cmd spring-boot:run
```

이 프로젝트는 .env를 자동으로 읽지 않는다. .env.example은 설정 예시다.
인증키는 URI 변수로 한 번 인코딩하므로 URL 인코딩된 Encoding 키를 넣으면 이중 인코딩될 수 있다.
실행을 마치면 다음 일반 서버 시작 전에 MFDS_IMPORT_ON_STARTUP을 false로 되돌린다.

## 저장·갱신 규칙

- external_code는 MFDS-EDRUG:품목기준코드 형식이다.
- 첫 적재 시 새 UUID를 부여하며 동일 품목의 재적재·수정 시 UUID를 유지한다.
- 내용이 같으면 unchanged로 집계한다. 출처 수정일이 더 오래됐거나 기존 날짜가 있는데 새 날짜가 없으면 덮어쓰지 않는다.
- 수정일은 원본 날짜를 Asia/Seoul 자정으로 해석해 UTC Instant로 저장한다. 실제 변경 시각의 정밀도를 뜻하지 않는다.
- 경고와 주의사항은 precautions에 줄바꿈으로 합친다. 상호작용은 interactions에 따로 저장한다.
- 기본 HTML 태그·엔티티를 일반 텍스트로 변환한다. 앱에서도 설명을 일반 텍스트로 표시한다.
- 출처가 제공하지 않은 성분·제형·외형은 추정하거나 AI로 생성하지 않는다. 기존 별도 정보는 유지한다.
- 비활성 약품을 갱신해도 자동으로 다시 활성화하지 않는다.
- 수집 응답에 없다는 이유로 기존 데이터나 시연 데이터를 삭제·비활성화하지 않는다.
- 시연 데이터와 공공 출처 데이터는 함께 남으며 상세 sourceName으로 출처를 구분한다.

## 오류·검증·실행 이력

V7에 drug_import_runs 테이블과 medication_products.interactions, record_version을 추가했다.
현재 실행용 테이블은 12개다. 전체 59개 테이블 설계 문서와 별도다.

실행 이력은 run ID, 상태, 시작·종료 시각, 마지막 완료 페이지, 생성·갱신·변경 없음·반려 건수와 고정 오류 코드만 저장한다.
API 키, 원본 요청 URL, 원본 오류 본문은 이력이나 애플리케이션 예외에 넣지 않는다.
HTTP 디버그 로깅·프록시 접근 로그 등 외부 로깅 설정에서도 요청 쿼리의 인증키가 노출되지 않도록 관리해야 한다.

| 상태 | 의미 |
| --- | --- |
| RUNNING | 실행 중. 프로세스가 비정상 종료되면 이 상태로 남을 수 있음 |
| COMPLETED | 요청 범위의 마지막 페이지까지 처리, 반려 없음 |
| COMPLETED_WITH_REJECTIONS | 마지막 페이지까지 처리했으나 일부 행이 입력 검증에서 제외됨 |
| PARTIAL | 최대 페이지 제한으로 중단. 다음 시작 페이지 확인 필요 |
| FAILED | 외부 응답·통신·저장 실패. 마지막 완료 페이지와 오류 코드 확인 |

- HTTP 연결 5초·응답 대기 10초, 페이지당 응답 최대 10MiB.
- 응답 코드, 페이지 번호, 총건수, 예상 행 수를 확인한다. 인증 오류 XML·잘못된 JSON을 빈 목록으로 처리하지 않는다.
- 필수 품목코드/제품명, DB 문자열 크기, 이미지 HTTP(S) URL, 수정일 형식을 검증한다.
- 유효하지 않은 행은 반려 건수로 집계한다. 개별 반려 본문을 따로 보관하는 기능은 아직 없다.
- 페이지 단위 트랜잭션으로 제품 변경과 이력 카운터를 함께 커밋한다. 실패 페이지는 롤백하고 앞서 완료한 페이지는 유지한다.
- 한 프로세스 내 중복 실행을 거절한다. 여러 인스턴스에서 동시에 실행하지 않는다.
- 다른 프로세스에서 같은 품목을 동시에 갱신하면 유니크 제약·낙관적 잠금으로 충돌을 감지해 페이지를 실패 처리한다. 자동 병합·무한 재시도는 하지 않는다.
- 원본 목록은 실행 중 달라질 수 있다. 재개 후에는 1페이지부터 재실행해 누락 가능성을 점검한다.

기록 확인용 SQL:

```sql
SELECT HEX(id) AS run_id, status, started_at, finished_at, last_completed_page,
       created_count, updated_count, unchanged_count, rejected_count, error_code
FROM drug_import_runs
ORDER BY started_at DESC;
```

FAILED/PARTIAL 실행은 last_completed_page + 1을 MFDS_IMPORT_START_PAGE로 지정해 재개할 수 있다.
첫 페이지부터 재실행해도 품목코드 기준으로 중복 제품을 만들지 않는다.
명시적 적재가 FAILED이면 시작 오류로 보고하므로 플래그를 해제하기 전에 원인을 확인한다.

## 검증 범위와 남은 작업

- HTTP 모의 응답으로 키 인코딩, 오류·잘못된 응답·불완전 페이지 거절 및 키 비노출을 검증.
- 실제 DB에서 신규·반복·변경·오래된 응답, 부분 실패, 페이지 롤백, 비활성 유지 및 동시 갱신 충돌을 검증.
- 구체적인 테스트 개수·실행 결과는 DEVELOPMENT_LOG.md 참고.
- 실제 인증키로 제공자 응답·승인·트래픽·전체 품목 수와 표시 내용을 확인해야 한다.
- 처방약·성분·외형 데이터는 추가 공식 데이터 출처를 선정하고 매핑해야 한다.
- 이 기능은 적재 실행 코드이며 실제 전체 공공 데이터 적재 완료를 뜻하지 않는다.
