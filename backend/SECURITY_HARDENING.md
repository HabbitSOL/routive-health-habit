# 백엔드 보안 보완 · 2026-10-18

## 적용 범위

`fix/backend/auth-security-hardening`에서 develop 기준으로 분리한 보안 보완이다.
로그 비노출·배포 설정 가드·SMTP 암호화·로그인 제한과 해당 테스트만 포함한다.
복약 행동·자동 회차 생성과 CI 재시도 변경은 별도 PR에서 관리한다. 병합·배포 여부는 PR 상태와 별개로 확인한다.

## 변경

- 콘솔 메일 발송기는 수신자·토큰·링크를 출력하지 않는다. 콘솔 모드에서는 실제 메일을 보내지 않으므로 인증 시연에는 SMTP가 필요하다.
- `local`, `test`, `mariadb-test`만 선택된 격리 환경 외에는 개발/테스트 JWT 키, 비SMTP 발송, HTTP 인증 링크, 선택적 SMTP STARTTLS 설정으로 시작할 수 없다. `local,prod` 혼합도 예외를 허용하지 않는다.
- SMTP STARTTLS를 필수로 설정한다. 암호화를 지원하지 않는 서버로의 발송은 실패한다. 실제 SMTP 서버 호환성은 별도 검증 대상이다.
- 로그인 컨트롤러는 DB 조회·비밀번호 해시 검증 전에 제한한다. 60초 고정 창 기준 계정 10회, 원격 주소 60회, 프로세스 전체 300회. 성공·실패·미가입 계정 모두 집계하며 429/TOO_MANY_REQUESTS를 반환한다.
- 제한기는 원문 이메일/IP 대신 SHA-256 키를 메모리에 보관하며 만료 항목을 정리한다. 최대 10,000개 도달 시 거부한다. 임의 전달 헤더는 신뢰하지 않는다.
- API 요청/성공 응답 및 DB 스키마 변경은 없다. 신규 오류 응답 429를 앱에서 처리해야 한다.

## 실행 설정

로컬 실행은 `--spring.profiles.active=local`을 명시한다. 이 프로필은 운영에서 사용하지 않는다.
테스트 클래스패스는 기본 `test` 프로필을 사용한다. 실제 서버에서는 테스트 프로필을 활성화하지 않는다.
운영에는 별도 난수 JWT_SECRET, MAIL_MODE=smtp, SMTP 접속 정보, HTTPS 인증/재설정 URL이 필요하다.
이 가드는 키의 엔트로피, 외부 HTTPS 프록시·인증서 또는 SMTP 수신함 도착을 증명하지 않는다.

## 남은 위험 및 결정

- 제한기는 단일 프로세스 기준이다. 재시작 시 초기화되며 여러 인스턴스는 카운터를 공유하지 않는다. 운영 게이트웨이/공유 저장소 제한이 필요하다. 프록시 뒤에서는 원격 주소가 프록시 주소이므로 정상 사용자도 공동 제한될 수 있다. 신뢰 프록시 정책 설정 전 운영 적용을 검토한다.
- 로그인 제한으로 계정별 반복 시도를 완화했으나 BCrypt 수행 중 사용자 잠금 구조는 유지된다. 공격자가 계정별 한도를 소진하는 일시적 로그인 방해 가능성도 남는다.
- 회원가입 중복 응답은 기존 계약(409)을 유지한다. 성공 응답의 사용자 ID/상태까지 포함해 통일하는 API 계약 변경이 후속이다.
- 서버 동의 문서/버전 레지스트리와 실제 공개 문서의 확정이 필요하다. 임의 버전 허용 문제는 이번에 해결하지 않았다.
- 갱신 토큰 재사용 시 세션 폐기 정책은 동시 갱신/정상 재전송 처리와 함께 후속 설계한다.
- 복약 일정 이력·회차 페이지 처리, 의존성 보안 업데이트 적용성, 운영 DB 권한/로그 보관은 후속이다.
- 기존 로그에 토큰이 남아 있을 수 있으므로 운영자가 접근·보존 정책과 필요 시 세션/링크 무효화를 검토해야 한다. 이번 작업은 과거 로그 삭제나 운영 자격증명 교체를 하지 않는다.
